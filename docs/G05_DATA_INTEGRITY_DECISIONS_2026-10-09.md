# G05 local correction decisions — 9 October 2026

Baseline: `4516e46389a47fa0f46ef562b4da6a82577f0557`, branch `fix/g05-data-integrity-2026-10-08`. Work started on 8 October and continued after midnight in Europe/Istanbul. This document records implementation choices, not product acceptance or engineering approval.

Basis: current producers/consumers and the read-only `output/ARKEMX_G04_Veri_Sozlugu_2026-10-08.md`. G04 describes existing data and gaps against CORE-V1/CEM targets; it is not an implemented CEM specification. This change is a bounded local adapter contract, not completion of CEM v0.1.

* Revision: a source stamp must match both project ID and revision. Opening an old draft is not a new source observation. Import/account validation rejects conflicts; local recovery preserves original stamps and displays a warning. Automatic handoff and autosave cannot relabel unsupported sources. Coordination exports use the explicit project revision, check BIM/federation conflicts, and reject missing revisions.
* Units: `ARKEM-UNITS/1.0` declares m, m2, kN, kN/m2, plus grid-bay coordinates for plan elements and m for dimensional module inputs. This matches existing UI/calculation conventions documented in G04. Internal producers declare their known native units. External or legacy mm/unitless data is rejected, never silently converted. Other unit profiles and complete material/section dimensions remain outside this adapter.
* Identity: require nonempty unique program source IDs and clash GUIDs. Display order/name cannot create identity. Program instances use `program-space:<escaped source ID>:<instance>`; derived floor cores retain a separate namespace. Generated cores explicitly name their derivation (real floor level and contributing source space IDs), not a fictitious `vertical-core` source entity. Existing saved plan IDs are preserved, not automatically rewritten; legacy program linkage may require explicit rebuilding/review. RFI IDs use escaped project ID and GUID separated by `:`; the delimiter cannot collide with an encoded source ID. Legacy work states migrate only through a unique source GUID and a compatible recorded revision. Ambiguous or unidentified states do not transfer. Critical active BIM issues still cannot be closed by a review flag.
* Geometry: H03 transfers the selected floor plate, consistent with the editor's active-floor display. It retains the entire floor-plate collection, selected level and source kind. It rejects missing, duplicate or invalid plates instead of substituting another floor/grid. A grid is used only when no floor-plate collection exists. This is an explicit technical choice for the existing selected-floor handoff, not a full-building geometry model.
* Calculation boundary: H03 invalidates prior results when its inputs change. The current structural engine assumes uniform repeated floor plates. Nonuniform plates are preserved and explicitly unsupported for that analysis; result/structural-studio transfer is blocked, JSON results are null, and PDF/CSV technical result exports are rejected. The UI visualization remains conceptual and displays this limitation. B06 therefore remains partly open for a genuine per-floor calculation/representation implementation.
* References: H03 retains actual input element IDs and original source revision. `calculationId` stays null until a traceable calculation record exists. Document reference status is unsupported when references/revisions are missing or invalid. Structural JSON and PDF expose the limitation. Declared references are not verification. No substitute calculation IDs, model references or authority approvals are manufactured. B04 remains open for the complete versioned element–calculation–document graph and its change-impact tests.

Tests: preserve pre-fix failing results; the same 20-case suite is replayed against Git HEAD without corrections and against corrected sources. Existing engineering/issue/storage regressions are run separately. Actual localhost Edge/Playwright tests cover floor geometry, source reorder, page reload, work-state persistence and explicit rejection. Fixtures are synthetic software regressions, not real project engineering evidence.
