# B06 S4-A01 — persistent floor identity and project shell source validation

Date: 2026-10-10. Input: synthetic project; no real project file supplied.

Implemented scope is source validation only. It does not solve a project shell, bind a project calculation/document record, couple shells to frames, or establish engineering approval. B06 as a whole remains open.

## Floor identity

- New program handoffs and new/rebuilt plans allocate `floorPlates[].id`. Resizing, reordering and rebuilding an existing floor retain its identity. Removing a floor and subsequently recreating it through the creation helper allocates a fresh identity.
- Legacy plans retain their saved geometry and missing IDs on load. The explicit **Eski döşemelere kalıcı kimlik ver** action performs a deterministic migration by project and floor level. Existing IDs are retained; invalid/duplicate IDs or levels fail rather than being repaired silently.
- Identity migration changes the source geometry snapshot. Saved floor coordination, frame/study sources and calculations must be reviewed against the new snapshot. The user explicitly re-saves floor coordination; no calculated record is automatically relinked.

## Project shell source contract

`ARKEM-PROJECT-SHELL-SOURCE/1.0` binds `projectId`, `revision`, `sourcePlateId`, optional explicit same-floor `sourceElementIds`, current plan basis and common floor placement. It requires the plan module's matching project/revision stamp and explicit metre/grid-bay source units. Selecting a different display floor, reordering source collections or storing another shell declaration does not change the binding. Changing source geometry, elements, common placements, project revision or coordinate reference invalidates it.

The initial supported shape is an unrotated rectangle parallel to XY. Width/depth and plate identity must match the selected source floor. Mid-surface Z is explicitly declared as floor-placement Z plus `midSurfaceReference.offsetZ`; missing offset is not treated as zero. Openings, polygons, rotations, point-column supports and unknown source fields are rejected.

The following are required declarations: thickness; material identity/name, E, Poisson ratio and unit weight; bounded mesh nx/ny; SS-H or CL edge restraint; slab self-weight choice; separate superimposed dead, live and benchmark area loads. Declared edge supports are independent pilot boundary conditions, not evidence that project columns provide those restraints. Optional element references establish provenance only, not support or coupled stiffness connectivity.

Blank drafts carry `null` for unknown physical values, support, provenance and mid-surface offset. Explicit zero loads and offset are valid. Numerical overflow, underflow, indistinguishable mesh coordinates and lost offsets fail before any solver is eligible.

`provenance.kind` distinguishes an explicitly marked synthetic project from a user-declared project reference. A user declaration is not an authenticated source file or approval. Synthetic projects cannot be relabeled as real through the shell source. `fullBuildingAnalysis` and `technicalApproval` must both be false.

## UI and storage

On `/plan-ve-aks`, review **Döşeme kimlikleri**, save current common floor coordinates, then use **Proje döşemesinin kabuk kaynağı**. Create a blank draft, fill explicit inputs or import JSON, and select **Kabuk kaynağını doğrula ve kaydet**. Invalid submissions leave previously saved declarations intact. The selected plate must match the submitted source.

Small source declarations are stored separately by plate in `plan-editor.projectShellSources`, using the existing checksummed project envelope. Saving a second plate retains the first. Reload revalidates the declaration against the current source. No raw numerical solution is stored here; large-result persistence remains S4-A03.

The legacy isolated `ARKEM-SHELL-SOURCE/1.0` and `/1.1` contracts, source/calculation hashes and S3 example document flow are unchanged. Only their physical declaration checker is shared. The project source contract cannot be supplied directly to the existing synthetic-only solver.
